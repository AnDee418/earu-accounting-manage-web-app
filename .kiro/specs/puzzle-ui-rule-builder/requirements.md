# Requirements Document

## Introduction

現在のルール作成フォームは複数の条件フィールドが並んでいるだけで、条件間の論理関係（AND/OR）が不明確で、ユーザーにとって理解しにくい状態です。この機能では、パズルのピースを組み合わせるような直感的なUIを実装し、「サルでもわかる」レベルの分かりやすさを実現します。

## Requirements

### Requirement 1

**User Story:** ルール作成者として、条件の論理関係を視覚的に理解できるパズル型UIを使いたい、そうすることで複雑なルール条件を直感的に組み立てることができる

#### Acceptance Criteria

1. WHEN ユーザーがルール作成フォームを開く THEN パズルピース型の条件ブロックが表示される
2. WHEN ユーザーが条件ブロックを追加する THEN 各ブロックが異なる色とアイコンで視覚的に区別される
3. WHEN ユーザーが複数の条件ブロックを配置する THEN ブロック間の論理演算子（AND/OR）が視覚的に表示される
4. WHEN ユーザーがAND演算子を選択する THEN 緑色で「すべて満たす」という説明が表示される
5. WHEN ユーザーがOR演算子を選択する THEN オレンジ色で「どれか満たす」という説明が表示される

### Requirement 2

**User Story:** ルール作成者として、条件の種類を直感的に選択したい、そうすることで適切な条件を素早く設定できる

#### Acceptance Criteria

1. WHEN ユーザーが条件追加ボタンを見る THEN 各条件タイプが分かりやすいアイコンと色で表示される
2. WHEN ユーザーが経費種別条件を追加する THEN 💰アイコンと緑色で「経費種別」ブロックが作成される
3. WHEN ユーザーが取引先条件を追加する THEN 🏪アイコンと青色で「取引先」ブロックが作成される
4. WHEN ユーザーが摘要キーワード条件を追加する THEN 🔍アイコンとオレンジ色で「摘要キーワード」ブロックが作成される
5. WHEN ユーザーが金額範囲条件を追加する THEN 💴アイコンと紫色で「金額範囲」ブロックが作成される
6. WHEN ユーザーが領収書内容条件を追加する THEN 📄アイコンとグレー色で「領収書内容」ブロックが作成される

### Requirement 3

**User Story:** ルール作成者として、作成したルールの動作を自然言語で確認したい、そうすることでルールが意図通りに動作するかを検証できる

#### Acceptance Criteria

1. WHEN ユーザーが条件ブロックを配置する THEN 画面下部にルールの読み方が自然言語で表示される
2. WHEN ユーザーが「経費種別が駐車場代 AND 取引先がパーキング」を設定する THEN 「経費種別 (駐車場代) AND 取引先 (パーキング)」と表示される
3. WHEN ユーザーが「金額が1000円以上 OR キーワードに電車が含まれる」を設定する THEN 「金額範囲 (1000円〜∞円) OR 摘要キーワード (電車)」と表示される
4. WHEN ユーザーが条件を変更する THEN リアルタイムで自然言語の説明が更新される

### Requirement 4

**User Story:** ルール作成者として、条件ブロックの順序を変更したい、そうすることでルールの優先順位を調整できる

#### Acceptance Criteria

1. WHEN ユーザーが条件ブロックをドラッグする THEN ブロックの順序を変更できる
2. WHEN ユーザーがブロックを移動中 THEN 挿入可能な位置がハイライト表示される
3. WHEN ユーザーがブロックを削除する THEN 削除ボタンをクリックしてブロックを削除できる
4. WHEN ユーザーが論理演算子を変更する THEN ドロップダウンでAND/ORを切り替えられる

### Requirement 5

**User Story:** 初心者ユーザーとして、パズル型UIの使い方を理解したい、そうすることで迷わずにルールを作成できる

#### Acceptance Criteria

1. WHEN ユーザーがヘルプボタンをクリックする THEN 使い方の説明が表示される
2. WHEN ユーザーが条件ブロックが空の状態を見る THEN 「パズルのピースを組み合わせるように」という説明が表示される
3. WHEN ユーザーが各条件タイプのボタンにホバーする THEN 具体例がツールチップで表示される
4. WHEN ユーザーが条件入力フィールドを見る THEN プレースホルダーに具体例が表示される

### Requirement 6

**User Story:** ルール作成者として、既存のルール条件データと互換性を保ちたい、そうすることで既存のルールが正常に動作し続ける

#### Acceptance Criteria

1. WHEN 既存のルールデータを読み込む THEN 従来の条件形式（expenseTypePatterns等）が正しくパズルブロックに変換される
2. WHEN パズルブロックで作成したルールを保存する THEN 従来の条件形式とパズルブロック形式の両方が保存される
3. WHEN 既存のルールを編集する THEN パズルブロック形式で表示・編集できる
4. WHEN ルールエンジンが条件を評価する THEN パズルブロック形式と従来形式の両方に対応する

### Requirement 7

**User Story:** ルール作成者として、複雑な条件の組み合わせを視覚的に理解したい、そうすることで論理エラーを防げる

#### Acceptance Criteria

1. WHEN ユーザーが複数のAND条件を設定する THEN 条件ブロック間が緑色の線で繋がれる
2. WHEN ユーザーが複数のOR条件を設定する THEN 条件ブロック間がオレンジ色の線で繋がれる
3. WHEN ユーザーがANDとORが混在する条件を設定する THEN 各演算子に応じた色の線で繋がれる
4. WHEN ユーザーが条件の優先順位を確認する THEN 上から下への順序で評価されることが視覚的に分かる
